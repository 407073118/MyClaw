# Cloud Web UI 规范

本文件约束 `apps/cloud-web` 管理台页面的基础信息架构，避免不同资源页各自发明列表与详情交互。

## 管理台列表页

- 列表页负责搜索、筛选、排序、创建入口和摘要浏览。
- 列表页不内嵌右侧详情预览，避免页面同时承担发现、阅读和编辑三种职责。
- 列表卡片只保留查看详情，不放编辑、发布、配置等维护动作。
- 卡片点击或“查看详情”进入独立详情路由，交互形态参考 `pages/skills/index.vue`。

## 管理台详情页

- 详情页负责完整信息展示、编辑入口和维护动作。
- 编辑入口只放在详情页，列表外层不直接编辑资源。
- 新建资源后，如果还需要维护扩展配置，应跳转到详情页继续编辑。

## 项目页约束

- `pages/projects/index.vue` 是项目列表页，只展示项目摘要卡片和新建项目入口。
- `pages/projects/[id]/index.vue` 是项目详情页，展示仓库、融智链、接口、Skills、MCP、工作流和硅基员工维护信息。
- 项目配置编辑只从项目详情页进入 `pages/projects/[id]/edit.vue` 后触发。

## 项目配置编辑器设计原则

- 项目配置编辑器是运维型管理台，不是展示型落地页；默认界面必须服务扫描、比较、定位和维护。
- 已保存的仓库、服务端点、接口、Skill、MCP 必须默认呈现为紧凑行，不允许把每一条数据永久展开成完整表单卡片。
- 新增或编辑是临时状态；用户保存或取消后，界面必须回到只读行态，避免页面堆满输入框。
- 行级操作放在行尾：高频操作直接露出编辑图标，删除、复制、禁用等低频或高风险操作进入更多菜单或二次确认。
- 行态只展示识别和判断所需字段，长说明、JSON Schema、覆盖配置、版本详情等复杂内容进入抽屉、弹窗或可展开详情。
- 编辑器内不使用“卡片套卡片”的布局。大区块可以是页面分区，单条资源用表格行、列表行或抽屉表单表达。
- 页面上的文字说明要服务业务理解，不写“如何使用本页面”的说明性长文；交互含义应由按钮、图标、标签和状态自然表达。
- 新增入口位于对应分区标题栏右侧，按钮文案使用“新增服务”“新增接口”“绑定 Skill”“绑定 MCP”等业务动作。

## 项目配置资源表

- 服务端点表字段：服务名称、Base URL、状态、说明摘要、操作。
- 代码仓库表字段：仓库名称、仓库类型、默认分支、地址、状态、操作。
- 接口表字段：方法、路径、接口名称、所属服务、标签、状态、操作；请求/响应 Schema 不在行内铺开，只在详情抽屉或编辑弹窗维护。
- Skill 表字段：Skill 名称、来源标识、版本、启用状态、覆盖配置摘要、操作。
- MCP 表字段：MCP 名称、别名、版本、风险等级、启用状态、覆盖配置摘要、操作。
- 表格第一列必须能识别资源本体；操作列不展示可见表头，宽度只由图标操作决定。
- 行内容保持短文本优先；长 URL、长路径和长说明需要截断、换行或 Tooltip，不能把行高撑成表单块。
- 移动端或窄屏下允许退化为列表行，但每条仍保持“摘要 + 状态 + 行级操作”，不能退化成完整大表单卡片。

## 新增与编辑流程

- 新增资源时打开右侧抽屉或居中弹窗，只收集创建所需的最小字段；确认后立即追加为一行摘要。
- 编辑已有资源时优先使用抽屉或弹窗；字段很少且互不依赖时才允许行内编辑。
- 行内编辑一次只能编辑一行；编辑态行需要明显区别于只读行，并提供保存与取消图标。
- 保存成功后关闭编辑态并刷新该行摘要；保存失败时错误停留在当前编辑容器内，不把用户带回顶部。
- 删除必须有确认；删除成功后该行从列表消失，列表滚动位置不应大幅跳动。
- 启用/禁用使用开关或状态按钮，不使用大块文本按钮挤占行宽。

## 视觉密度与状态

- 项目配置表的常规行高目标为 44-56px；包含二级信息的列表行不超过三行文本。
- 分区标题包含名称、数量和主要新增动作；筛选、搜索、批量操作放在分区工具栏，不混入资源行。
- 空状态必须说明当前分区没有数据，并提供同一分区的新增入口。
- 加载态使用骨架行或轻量占位，形状尽量接近真实行，避免加载完成后布局大幅跳动。
- 危险操作使用低饱和危险色和确认流程，不能把删除做成醒目的主按钮。
- 图标按钮必须有可访问名称或 Tooltip；仅靠图标无法表达风险时，更多菜单项使用文字。

## 与 Hub 风格的一致性

- Hub 用于发现和进入资源，项目编辑器用于维护资源；二者都应遵守“列表摘要优先、详情按需展开”的信息结构。
- 项目页不能使用营销式 Hero、装饰性大卡片或大面积空白；它应像 Hub 的管理台一样强调资源关系、数量、状态和下一步动作。
- 颜色、圆角、阴影和按钮层级必须复用 `apps/cloud-web` 的全局 token；如果现有 token 不足，先补 token，再写页面局部样式。

## 项目配置编辑器验收标准

- 添加任意服务端点、接口、Skill 或 MCP 后，页面中出现的是一行新资源摘要，而不是一张永久展开的大表单卡片。
- 每个资源行至少有编辑入口和删除入口；删除有确认，编辑有保存和取消。
- 同一时间最多存在一个行内编辑态；抽屉或弹窗编辑不影响其它资源行的可读性。
- 页面在 1366px 桌面宽度下能同时看到多个资源行，不能一屏只显示一到两条配置。
- 页面在 390px 移动宽度下不出现文字重叠、按钮溢出或横向不可控滚动。
- 后续实现需要用页面测试或组件测试覆盖“新增后回到行态”“编辑保存后回到行态”“删除确认”三个核心路径。

## 外部参考

- [Ant Design Table](https://ant.design/components/table/?locale=en)：结构化数据使用表格承载，支持排序、筛选、分页、可编辑行和操作列。
- [Material Design Data tables](https://m1.material.io/components/data-tables.html)：数据表由表头和数据行组成，桌面场景支持行悬停、选择、文本编辑、菜单和表格内操作。
- [PatternFly Table](https://www.patternfly.org/components/table/) 与 [PatternFly Inline edit](https://v4-archive.patternfly.org/v4/components/inline-edit/design-guidelines/)：行编辑由编辑图标触发，编辑完成后保存或取消并回到只读行态，行级操作放在最后一列。
- [Primer Data table](https://primer.github.io/design/components/data-table/)：行是资源本体，列是数据点；行级操作位于最后一列，多操作进入下拉菜单，高频操作才外露。
- [Shopify Polaris Table](https://shopify.dev/docs/api/app-home/web-components/layout-and-structure/table)：表格先定义表头再定义数据行，并为移动端列表化展示保留主字段、状态和标签位。
