<objective>
Parse `.docx` into DocumentIR. Mammoth alone flattens tables and drops comments/footnotes, so we combine:
1. mammoth for heading + paragraph detection (style-aware)
2. Direct ZIP + XML read of `word/document.xml`, `word/comments.xml`, `word/footnotes.xml`, `word/_rels/document.xml.rels` to recover table cells, comments, footnotes, and image references

Keep it zero-Python. Expected package additions: `mammoth` (~500KB). ZIP handling uses `node:zlib` + a tiny in-tree ZIP reader or an existing lightweight library (`jszip` is acceptable if already transitively present; prefer a minimal in-file ZIP reader to avoid dep inflation — mammoth itself ships jszip transitively, so if `require("jszip")` resolves, use it).
</objective>

<interfaces>
DocumentIR node kinds (from 08-01):
- HeadingNode, ParagraphNode, ListNode, TableNode, CommentNode, FootnoteNode, ImageNode
All carry `locator` — for docx use `locator.heading` at heading boundaries; for body nodes between headings, populate `locator.heading` with the most recent heading's text.

mammoth API (after pnpm add):
```ts
const mammoth = require("mammoth");
const result = await mammoth.convertToHtml({ buffer });
// result.value = HTML string; result.messages = warnings
```
We prefer mammoth's `extractRawText` + style info by using `convertToHtml` and parsing heading levels from `<h1>..<h6>` tags. Tables from mammoth's HTML are also usable as a starting point; augment with XML for edge cases.

XML security: all XML parses must be done with a parser that does NOT resolve external DTD / entities. Use `fast-xml-parser` (if available) with `processEntities: false, allowBooleanAttributes: false, ignoreDeclaration: true, stopNodes: []` — or implement a minimal hand rolled tag walker. fast-xml-parser is likely a mammoth transitive — check with `require.resolve("fast-xml-parser")`. If neither jszip nor fast-xml-parser is available transitively, add them as explicit deps.

       ```ts
       import { writeFile } from "node:fs/promises";
       import { join } from "node:path";
       import type { DocumentIR, HeadingNode, ParagraphNode, TableNode, CommentNode, FootnoteNode, ImageNode, MediaRef, InlineRun, OutlineItem } from "@shared/contracts";
       import type { DocumentParser, ParseInput } from "../parser-registry";

       export async function parseDocxBuffer(input: ParseInput): Promise<DocumentIR> {
         // 0. XXE check: scan first 4KB of buffer as UTF-8 for "<!DOCTYPE" — if found, throw [E_DOC_XXE_BLOCKED]
         // 1. Require mammoth; convertToHtml({ buffer })
         // 2. Parse the resulting HTML (use a minimal regex-based walker for <h1>..<h6>, <p>, <ul>/<ol>, <table>, <img src="..."> — the whole HTML is our own trusted output, no DOCTYPE expected)
         //    - For each h1..h6: emit HeadingNode with level = parseInt(tagName[1])
         //    - For p: ParagraphNode
         //    - For ul/ol: ListNode (ordered = tagName === "ol")
         //    - For table/tr/td: TableNode
         //    - For img with src starting "data:image/": decode base64 -> write to input.mediaDir with sha-derived filename -> ImageNode + MediaRef
         // 3. Load docx as zip (try `require("jszip")`; fallback: add to package.json and install). Read:
         //    - word/comments.xml -> CommentNode[]
         //    - word/footnotes.xml -> FootnoteNode[] (skip the auto "separator" + "continuationSeparator" footnote kinds)
         //    Append these nodes to body at the end (mammoth HTML doesn't include them).
         // 4. Populate locator.heading on all non-heading body nodes: track lastHeading text while walking; set on each ParagraphNode/ListNode/TableNode/ImageNode.
         // 5. Build outline from headings (level + title + locator { heading: title }).
         // 6. meta.words = approximate via sum of run text lengths / 5.

         // Return DocumentIR with format="docx"
       }

       export const docxParser: DocumentParser = { format: "docx", parse: parseDocxBuffer };
       ```

       Implementation notes:
       - HTML tag walker: use a simple stack-based regex over `<(\/?)(tag)([^>]*)>` — do NOT use an XML/HTML external parser on untrusted DOCX content. The HTML mammoth produced is trusted (it's our own library's output), so regex is acceptable here.
       - For comments/footnotes XML, implement a minimal safe reader:
         ```ts
         function extractTextNodes(xml: string, tag: string): Array<{ id: string; author?: string; text: string }> {
           // Refuse if xml contains "<!DOCTYPE"
           // Match all <w:tag w:id="..." w:author="...">...<w:t>text</w:t>...</w:tag>
           // Collect w:t content, strip tags; return.
         }
         ```
       - Each extracted image: filename `<sha256-of-data>.<ext>`; `mediaId` = same sha256; `cachePath` = relative path like `media/<filename>`.
