<objective>
Close the model-guidance side of the phase: make sure the model cannot accidentally fall back to Python scripts or raw fs_read for documents. This is the "C 引导与拦截" stage.

Three concrete shifts:
1. `fs.read` hitting `.xlsx/.xls/.xlsm/.docx/.pdf/.pptx` is HARD-REJECTED (today the dispatch already refuses binary files but with a soft "suggestedTool" hint — upgrade to a templated `document.read` invocation in the error message, and include the error code `E_DOC_USE_DOCUMENT_READ`).
2. `buildSkillExecutionGuidance` (lines 619-634) no longer treats `py -3` as first choice. New guidance:
   - Prefer node-based structured tools (`document.read` for docs, `xlsx.extract` still works for xlsx)
   - Only mention py -3 as a LAST resort fallback, after enumerating the node path
3. `tool-schemas.ts` descriptions call out document.read in both `fs_read` and `xlsx_extract` entries, and the `document_read` description itself includes 4 ready-to-use example invocations.

None of this changes behavior for non-document files. xlsx.extract alias still works (from 08-04).
</objective>
